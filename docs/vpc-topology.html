3306 from the node group only, never 0.0.0.0/0. Outbound is unrestricted, as on the other three groups — the ingress rule is the restriction that matters, because nothing outside the node group can open a connection for that egress to answer.

Deliberate choices worth a second look

  • ✓Two public subnets, two AZs, public IP on launch — matches the CIDR table in the spec.
  • ✓Subnets carry kubernetes.io/cluster/petclinic-<env>=shared and kubernetes.io/role/elb=1, verified in the plan output.
  • ✓No NAT gateway, no private subnets, no VPC endpoints.
  • ✓Node SG ingress on 8080 from the ALB SG exists for the ALB's health checks. The Ingress sets target-type: ip with healthcheck-port: "8080", and under the default VPC CNI pod-IP traffic is governed by the node SG — without it every target goes unhealthy. Now a row in the spec's node table.
  • ✓All four groups have unrestricted egress — All / All / 0.0.0.0/0, matching the spec's table for each. Outbound is not where the perimeter is; every constraint in this document is an ingress rule naming a source group.
